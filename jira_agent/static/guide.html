Bootstrap your template

Von der Vorlage zur eigenen App und zur ersten Jira-Abfrage. Gehe die Abschnitte der Reihe nach durch.

Bevor du beginnst
  • Zugang zu deinem Databricks-Workspace und zu Jira.
  • Berechtigung, einen Git-Ordner und eine Databricks App anzulegen.
  • Zugriff auf Azure-OpenAI-Secret, SQL Warehouse und ein MLflow-Experiment. Lass die Ressourcen bei Bedarf vom Workspace-Admin freigeben.

Die Namen und IDs für deinen Workspace stehen in databricks.yml → variables. Das sind keine Jira-Zugangsdaten.

1. Code in den Workspace holen

Für eine eigene Weiterentwicklung erst eine eigene Kopie des GitHub-Repos erstellen (z. B. über „Use this template“, falls verfügbar, oder einen Fork). Verwende dann deren URL. Die URL unten bindet die gemeinsame Vorlage ein.

  1. Workspace öffnen

    Klicke links auf Workspace (1).

    Ergebnis: Die Ordneransicht öffnet sich.

  2. Deinen Benutzerordner öffnen

    Klappe Workspace → Users auf. Wähle den Ordner mit deiner eigenen E-Mail (1).

    Ergebnis: Du siehst deine Dateien und Ordner.

  3. Ordneraktionen öffnen

    Fahre über deinen Benutzerordner und klicke rechts auf die drei Punkte ⋮ (1).

    Ergebnis: Das Aktionsmenü erscheint.

  4. Git-Ordner wählen

    Wähle Erstellen (1) und anschließend Git-Ordner (2).

    Ergebnis: Der Dialog „Git-Ordner erstellen“ öffnet sich.

  5. Repository-URL einfügen

    Füge die URL ein (1). Prüfe Git-Anbieter und Ordnernamen, dann klicke Git-Ordner erstellen (2).

    https://github.com/CariadNayon/jira-agent-template.git

    Ergebnis: Der Git-Ordner erscheint in deinem Benutzerordner.

2. Eigene App anlegen

  1. Databricks-Apps öffnen

    Öffne oben rechts das Produktmenü (1) und wähle Databricks-Apps (2).

    Ergebnis: Die App-Übersicht erscheint.

  2. Neue App erstellen

    Klicke rechts oben auf App erstellen (1).

    Ergebnis: Die Auswahl zum Erstellen einer App öffnet sich.

  3. Benutzerdefinierte App auswählen

    Klicke die Kachel Benutzerdefinierte App erstellen (1).

    Ergebnis: Du kannst den Namen deiner App eingeben.

  4. App benennen

    Vergib einen eigenen Namen mit Kleinbuchstaben, Ziffern und Bindestrichen, z. B. agent-jira-team-x (1). Klicke App erstellen (2).

    Ergebnis: Deine App ist angelegt; der Code ist noch nicht bereitgestellt.

3. Ressourcen und Benutzerzugriffe einrichten

Öffne in der neuen App die Ressourcen-Konfiguration (je nach Workspace unter Konfigurieren oder Einstellungen). Füge diese Ressourcen hinzu. Die Ressourcennamen müssen genau übereinstimmen:

Name in der App Auswahl App-Berechtigung
secret Secret Scope und Key aus variables.secret_scope und variables.secret_key READ
sql-warehouse Warehouse aus variables.warehouse_id CAN_USE
experiment MLflow-Experiment für diese App CAN_MANAGE wie im Bundle

Öffne Autorisierung → Benutzerautorisierung. Füge die folgenden fünf Scopes hinzu. Ein Scope erlaubt der App eine bestimmte API im Namen des Benutzers aufzurufen.

sql:restricted-query
catalog.catalogs:read
catalog.schemas:read
catalog.tables:read
workspace.workspace

Ergebnis: Alle drei Ressourcen und fünf Scopes sind gespeichert. Bei der Anmeldung kann die App die Benutzerfreigabe anfordern.

Für diesen Teil fehlen noch Screenshots. Die Schritte sind deshalb als Text beschrieben. Details stehen unter App infrastructure & permissions.

5. Jira-Token erstellen und einfügen

Der Jira-Token ist dein persönlicher Zugang zu Jira. Er ist unabhängig vom Azure-Key und den Databricks-Scopes. Die folgenden Bilder zeigen die Jira-Oberfläche dieser Installation.

  1. Token-Verwaltung öffnen

    Öffne Jira im Browser. Klicke oben rechts auf dein Profilbild (1), dann auf API Token Authentication (2). In anderen Jira-Versionen heißt der Bereich ggf. „Personal Access Tokens“ im Profil.

    Ergebnis: Die Seite „My API tokens“ erscheint.

  2. Neuen Token anlegen

    Klicke auf New API Token (1).

    Ergebnis: Das Formular für einen neuen Token öffnet sich.

  3. Name, Ablauf und Rechte wählen

    Vergib einen erkennbaren Namen, z. B. „Mein Jira Agent“ (1), und wähle ein Ablaufdatum nach euren Vorgaben. Für Kommentare und andere Änderungen brauchst du Read & Write (2); für reine Abfragen genügt Read Only. Klicke Create API Token (3).

    Ergebnis: Jira zeigt den neuen Token einmalig an.

  4. Token kopieren

    Kopiere den erzeugten Token über das Kopiersymbol, bevor du die Jira-Seite verlässt. Bewahre ihn nach euren Vorgaben sicher auf. Füge ihn weder in den Chat noch in Screenshots oder den Code ein.

  6. Erste Abfrage testen

    Zeig meine offenen Jira-Tickets.

    Ergebnis: Der Agent liefert Tickets oder meldet, dass keine gefunden wurden. Er nimmt dabei keine Änderungen vor.

Nach Neustart oder Deployment

Der Jira-Token liegt nur im Arbeitsspeicher. Nach einem Neustart, nach dem Abmelden oder spätestens nach 8 Stunden musst du ihn erneut einfügen. Ein abgelaufener oder widerrufener Token muss in Jira neu erstellt werden.

Aktualisieren und für andere freigeben

Git-Ordner öffnen → Branch → Pull. Dann die App erneut bereitstellen und mit Strg+Shift+R neu laden. Unter Teilen / Berechtigungen legst du fest, wer die App nutzen darf. Jira- und Tabellenrechte erhalten andere dadurch nicht automatisch.

BUILD

Develop your agent with AI

Beschreibe eine konkrete Aufgabe. Lass dir die Änderung erklären und prüfe sie, bevor du sie bereitstellst.

Empfohlen: GitHub Copilot in VS Code

Hier kann der Assistent Projektdateien bearbeiten und Tests ausführen. Genie hilft bei Datenfragen. Falls in eurem Workspace Genie Code verfügbar ist, kannst du es für unterstützte Entwicklungsaufgaben verwenden; Funktionsumfang und Dateizugriff hängen vom Workspace ab.

  1. Eigene Projektkopie öffnen

    Öffne deine Kopie des Repos in VS Code und starte Copilot Chat. Nutze für Dateiänderungen den Agent-Modus, sofern verfügbar. Lokal brauchst du uv ≥ 0.9.17, Node.js 20+ und Databricks CLI.

    Ergebnis: Copilot kann die Dateien deiner Projektkopie lesen.

  2. Projektregeln mitgeben

    Verlasse dich nicht darauf, dass der Assistent alle Regeln automatisch lädt. Hänge AGENTS.md an den Chat an oder fordere ausdrücklich das Lesen an.

    Lies zuerst AGENTS.md und die zur Aufgabe passende Anleitung in .claude/skills/. Erkläre kurz, wie dieses Projekt aufgebaut ist. Ändere noch nichts.

    Ergebnis: Der Assistent kennt Projektaufbau und Sicherheitsregeln.

  3. Umgebung einrichten

    Richte das Projekt nach .claude/skills/einrichten/SKILL.md ein. Nutze meinen Databricks-Workspace und frage nach der URL, falls sie fehlt. Lege keine zusätzliche Datenbank an.

    Ergebnis: Die lokale Konfiguration und Databricks-Anmeldung sind eingerichtet.

  4. Eine Änderung beschreiben

    Baue ein Tool, das den Status eines Jira-Tickets ändert. Beispiel: ABC-123 auf „In Arbeit“. Lies .claude/skills/neues-tool/SKILL.md. Verwende die vorhandenen Jira-Helfer und write=True. Ergänze Tests ohne echtes Jira und führe sie aus.

    Ergebnis: Du erhältst eine überschaubare Änderung und Testergebnisse.

  5. Prüfen, lokal testen und bereitstellen

    Lass dir die geänderten Dateien und das Verhalten erklären. Teste eine lesende Anfrage und die Bestätigungsabfrage vor einer Änderung. Erst danach deployen.

    Führe uv run pytest tests -q aus und starte die App lokal. Zeige mir, wie ich die Änderung prüfe. Deploye noch nicht.
    Die Änderung ist geprüft. Lies .claude/skills/deploy/SKILL.md, prüfe das Deploy und stelle die App bereit.

    Ergebnis: Die geprüfte Version ist erreichbar. Nach dem Deploy Jira erneut verbinden.

Was lässt sich ohne Code ändern?

Über das Zahnrad kannst du Name, Modell, Regeln, freigegebene Tabellen und persönliche Skills ändern. Neue Aktionen brauchen ein Tool in jira_agent/tools/. Eine gespeicherte Anleitung für bestehende Aktionen braucht einen Skill.

Wo wird entwickelt?
Datei Aufgabe
jira_agent/tools/ Neue Aktionen; Vorlage example_custom_tool.py
tests/ Verhalten ohne echtes Jira prüfen
jira_agent/config.yaml Jira-URL, Modell und Limits
databricks.yml → variables App-Name, Secret und Warehouse

UNDERSTAND

What are skills?

Ein Skill ist eine gespeicherte Anleitung für eine wiederkehrende Aufgabe. Du rufst ihn im Chat mit /name auf.

Beispiel: Wochenreport

Statt jede Woche dieselbe Anleitung zu schreiben, sendest du /wochenreport letzte Woche. Der Agent erhält den gespeicherten Ablauf und deine Ergänzung.

Begriff Beispiel Was passiert?
Tool Jira-Tickets suchen Python-Code ruft Jira auf.
Skill Wochenreport Eine Anleitung legt fest, welche Tickets gesucht und wie sie zusammengefasst werden.
Regel „Antworten auf Deutsch“ Eine allgemeine Vorgabe aus den Einstellungen gilt für die Unterhaltung.

Ein Skill fügt keine neuen technischen Fähigkeiten oder Zugriffsrechte hinzu. Jira-Änderungen brauchen weiterhin die Bestätigung ja CODE.

Vorhandenen Skill verwenden

  1. Im Chat / tippen.
  2. Einen Skill auswählen, z. B. /triage, /wochenreport oder /ticket-zusammenfassung.
  3. Bei Bedarf Ticket oder Zeitraum ergänzen und senden.

Persönlichen Skill anlegen

Öffne Zahnrad → Skills → + Neuer Skill. Gib einen Namen, eine Kurzbeschreibung und die Anleitung ein. Beispiel:

Name: ticket-check
Beschreibung: Prüft, ob ein Ticket verständlich beschrieben ist

1. Lies das angegebene Ticket.
2. Prüfe, ob Problem, erwartetes Verhalten und Schritte zur Reproduktion vorhanden sind.
3. Liste fehlende Angaben auf. Ändere das Ticket nicht.

Speichere den Skill und nutze /ticket-check ABC-123. Persönliche Skills sind für dich bestimmt und werden mit deinen Databricks-Rechten in deinem Workspace-Benutzerordner gespeichert.

Einen Skill mit dem Team teilen

  1. Beim persönlichen Skill Für Team vorschlagen wählen. Das lädt eine Markdown-Datei herunter; es veröffentlicht sie noch nicht.
  2. Die Datei im KI-Chat deiner Projektkopie anhängen und diesen Auftrag senden:
Lies AGENTS.md und .claude/skills/team-skill/SKILL.md. Übernimm den angehängten Skill nach skills/, prüfe das Format und führe die Tests aus. Zeige mir die Änderung vor dem Deploy.

Nach Prüfung und Deployment sehen die Nutzer dieser App den Team-Skill in der /-Liste. Bei gleichem Namen hat der Team-Skill Vorrang.

Skill-Datei für Entwickler
---
name: ticket-check
beschreibung: Prüft ein Ticket auf fehlende Angaben
---
1. Lies das angegebene Ticket.
2. Nenne fehlende Angaben, ohne das Ticket zu ändern.

App-Skills in skills/ steuern den Jira-Agenten. Die Entwicklungsanleitungen in .claude/skills/ richten sich dagegen an den KI-Assistenten, der den Code bearbeitet.

App infrastructure & permissions

Die App nutzt zwei Arten von Zugriff: eigene App-Ressourcen für den Betrieb und deine persönlichen Rechte für Jira und Daten.

Du im Browser
↓ Databricks-Anmeldung
Chat-Oberfläche → Python-Agent
Jira
Dein Jira-Token
SQL Warehouse → Unity Catalog
Deine Databricks-Rechte
Azure OpenAI · MLflow
App-Ressourcen

Welche Komponente macht was?

Baustein Zweck Konfiguration / Rechte
Databricks App Hostet Chat und Python-Agent. App-Name in databricks.yml → variables.app_name; Nutzung unter Teilen freigeben.
App-Service-Principal Technische Identität der App. Zugriff auf die zugewiesenen Ressourcen; ersetzt keine Benutzerrechte auf Tabellen.
Azure OpenAI Erzeugt Antworten und wählt Tools. Endpoint/Deployment in jira_agent/config.yaml; Team-Key aus Ressource secret.
Secret Scope Bewahrt den Azure-Key auf. Scope = Gruppe von Secrets; Key = Eintrag darin. App-Ressource secret braucht READ. Werte in variables.secret_scope/secret_key.
SQL Warehouse Führt lesende SQL-Abfragen aus. Ressource sql-warehouse, ID in variables.warehouse_id. App: CAN_USE; auch der Benutzer benötigt CAN_USE.
Unity Catalog Verwaltet Kataloge, Schemas und Tabellen. Benutzer benötigt USE CATALOG, USE SCHEMA und SELECT auf den jeweiligen Objekten sowie die Freigabe unter Zahnrad → Datenquellen.
MLflow-Experiment Speichert Traces zur Fehlersuche. Ressource experiment; Bundle nutzt CAN_MANAGE. Traces können Chat-, Ticket- und Abfrageinhalte enthalten. Zugriff gezielt vergeben.
Jira Liest und bearbeitet Tickets. Persönlicher Jira-Token. Jira-Projektberechtigungen gelten weiterhin.

Benutzer-Scopes: erlaubte APIs

Die App fragt bei der Benutzerautorisierung diese API-Bereiche an. Sie erweitern deine eigenen Berechtigungen nicht.

Scope Verwendung
sql:restricted-query Lesende Abfragen mit deinen Rechten.
catalog.catalogs:read Kataloge auflisten.
catalog.schemas:read Schemas auflisten.
catalog.tables:read Tabellen und Metadaten anzeigen.
workspace.workspace Persönliche Einstellungen und Skills im Workspace-Benutzerordner speichern.
Drei Voraussetzungen für eine Tabellenabfrage
  1. Die App hat die passenden Benutzer-Scopes.
  2. Du darfst Warehouse, Katalog, Schema und Tabelle verwenden.
  3. Du hast die Tabelle unter Zahnrad → Datenquellen ausgewählt und gespeichert.

Eine ausgewählte Tabelle allein vergibt keine Rechte. Eine SQL-Abfrage läuft mit deinem weitergeleiteten Benutzer-Token.

Was wird wo gespeichert?

Jira-Token, temporäre Dateien und Bestätigungscodes liegen im Arbeitsspeicher. Deshalb genau einen Worker betreiben. Einstellungen und persönliche Skills liegen im Workspace-Benutzerordner. Team-Skills liegen im Repo. Die Speicherung des Chatverlaufs ist davon getrennt: Ohne optionale Datenbank arbeitet das Chat-Frontend ohne dauerhafte Verlaufsspeicherung.

Fehler eingrenzen
Symptom Prüfen
„x-forwarded-email“ fehlt Identitätsweitergabe zwischen Chat-Frontend und Python-Backend; aktuelle Version bereitstellen. Keine Nutzerkennung in eine Chatnachricht schreiben.
Jira-Verbindung scheitert Token korrekt kopiert, noch gültig und für diese Jira-Instanz erstellt? Nach Neustart erneut verbinden.
Keine Tabellen sichtbar Benutzerautorisierung, Katalog-/Schemarechte und Tabellenrechte prüfen.
SQL-Abfrage abgelehnt Warehouse-Zugriff, SELECT-Recht und Auswahl unter Datenquellen prüfen.
„Database not available“ Ohne optionale Chat-Datenbank wird der Verlauf nicht dauerhaft gespeichert. Weitere Fehlermeldungen separat prüfen.
App startet nicht App → Logs: Ressourcen-Namen, Azure-Konfiguration und letzte Bereitstellung prüfen.

Jira noch nicht verbunden? Zum Erstellen und Einfügen des Tokens.

3. Dateien anhängen

Über die Büroklammer neben dem Senden-Knopf, per Strg+V (z. B. aus dem Explorer kopiert) oder per Ziehen auf das Eingabefeld. Im Text erscheint [Datei: name] – dann einfach dazuschreiben, was der Agent damit tun soll.

Lesbar: CSV, Excel, PDF (Text), TXT/MD/JSON. Max. 20 MB. Dateien liegen nur im Speicher und verschwinden nach 60 Minuten.

4. Skills – gespeicherte Abläufe mit /

  • Aufrufen: im Chat / tippen → Liste erscheint → auswählen, ggf. etwas dazuschreiben, z. B. /wochenreport letzte Woche.
  • Team-Skills (für alle): z. B. /triage, /wochenreport, /ticket-zusammenfassung.
  • Eigene Skills: Zahnrad → Skills → + Neuer Skill. Name, Kurzbeschreibung und die Anleitung in Schritten – so, als würden Sie es einer Kollegin erklären. Nur für Sie sichtbar, bleibt dauerhaft gespeichert.
  • Fürs Team freigeben: beim Skill „Für Team vorschlagen“ → Datei wird heruntergeladen → siehe Skill fürs Team.

5. Änderungen bestätigen

Bevor der Agent etwas in Jira ändert, zeigt er genau, was passieren soll, und einen Code. Erst mit „Aktion bestätigen (ja CODE)“ bzw. der Antwort ja CODE wird es ausgeführt – sonst passiert nichts.

6. Einstellungen (Zahnrad oben rechts)

Zugänge Name des Agenten, Jira-Token, optional eigener Azure-Key, Abmelden.
Modell Team-Key (Standard) oder eigener Azure-OpenAI-Key.
Datenquellen Tabellen freigeben, die der Agent lesen darf – nur mit Ihren eigenen Rechten, nur lesend.
Regeln Ihre Regeln in einfacher Sprache, z. B. „Tickets zu Bremsen ohne Bearbeiter gehen an chassis.lead“.
Skills Eigene Skills anlegen, bearbeiten, löschen, fürs Team vorschlagen.

Name, Modell, Datenquellen und Regeln mit Speichern übernehmen – sie liegen (ohne Keys) in Ihrem Home-Ordner und gelten ab der nächsten Nachricht.
