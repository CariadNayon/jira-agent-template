1. Ohne Code: Name, Regeln, Daten

  • Zahnrad oben rechts → Zugänge: Name des Agenten, Jira-Token (nur für diese Sitzung), optional eigener Azure-Key.
  • Regeln: in einfacher Sprache, z. B. „Tickets zu Bremsen ohne Bearbeiter gehen an chassis.lead“.
  • Datenquellen: Tabellen freigeben, die der Agent lesen darf (nur mit Ihren eigenen Rechten).
  • Mit Speichern übernehmen – gilt ab der nächsten Nachricht.

2. Eigenes Tool hinzufügen

Neue Datei in jira_agent/tools/ anlegen, z. B. mein_tool.py. Sie wird automatisch geladen. Vorlage: jira_agent/tools/example_custom_tool.py.

from jira_agent.jira_client import JiraClient
from jira_agent.tools import ToolContext, tool


@tool("Setzt ein Label an einem Jira-Ticket, z. B. 'auto-routed'.",   # Beschreibung für das Modell
      {"issue_key": {"type": "string"}, "label": {"type": "string"}},  # Parameter (JSON-Schema)
      ["issue_key", "label"],                                           # Pflichtfelder
      write=True,                                                      # ändert etwas -> Bestätigung nötig
      needs=["jira"])                                                  # nur sichtbar mit Jira-Token
def jira_add_label(ctx: ToolContext, issue_key: str, label: str) -> dict:
    key = JiraClient.check_key(issue_key)
    r = ctx.jira.request("PUT", f"/issue/{key}", json={"update": {"labels": [{"add": label}]}})
    return {"status": "OK"} if r.status_code == 204 else {"error": r.status_code}
  • Erstes Argument ist immer ctx: ctx.jira (Jira-Client mit dem Token des Nutzers), ctx.sql (lesendes SQL mit Nutzerrechten: ctx.sql.query(...), ctx.sql.describe(...)), ctx.files (Datei zum Download ablegen: ctx.files.put(name, mime, bytes) liefert eine URL), ctx.selected_tables (freigegebene Tabellen).
  • needs: "jira", "sql" oder "files" – das Tool ist nur sichtbar, wenn das vorhanden ist.
  • write=True für alles, was etwas verändert: Der Agent muss dann vorher „ja <CODE>“ einholen. Das ist im Code erzwungen, Sie müssen nichts weiter tun.
  • Rückgabe: ein dict. Fehler einfach als Exception werfen – der Agent bekommt sie als Text.
  • Bilder oder Downloads: im Ergebnis ein Feld "markdown" zurückgeben, z. B. f"![Titel]({url})" – siehe output_tools.py.

4. Standardwerte ändern

jira_agent/config.yaml: Jira-URL, Azure-Endpoint und Deployment, Warehouse, Zeilenlimits, Standardregeln, Ablaufzeiten für Keys und Dateien. Nutzer überschreiben Regeln, Name, Modell und Tabellen persönlich im Zahnrad.

5. Eigene Kopie der App

  1. Den Quellordner der App (mit agent_server/, jira_agent/, app.yaml, pyproject.toml) kopieren.
  2. Compute → Apps → Create app, Quellordner wählen.
  3. App-Ressourcen mit genau diesen Namen hinzufügen:
    • secret – Secret defmgtai-eu-we-dev-adb-local-secret-scope / gpt-4-api-key, Can read
    • sql-warehouse – SQL Warehouse, Can use
    • experiment – MLflow-Experiment für Traces, Can edit
  4. User authorization – Scopes: sql:restricted-query, catalog.catalogs:read, catalog.schemas:read, catalog.tables:read, workspace.workspace.
  5. Deploy – nach jeder Code-Änderung erneut deployen und die Seite mit Strg+Shift+R neu laden.

Die App mit einer Instanz betreiben: Keys liegen nur im Arbeitsspeicher und gehen bei Neustart oder Deploy verloren.

6. Sicherheitsregeln

  • Keine Keys oder Tokens in Code, Logs, Tool-Ergebnissen oder settings.json.
  • Alles, was in Jira oder anderen Systemen etwas ändert, mit write=True markieren.
  • SQL nur über ctx.sql und check_readonly_sql (nur SELECT, nur freigegebene Tabellen).
  • Eingaben prüfen, z. B. JiraClient.check_key() für Ticket-Keys.
