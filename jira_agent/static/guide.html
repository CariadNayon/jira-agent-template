Bootstrap your template

Go from the template to your own app and your first Jira query. Follow the sections in order.

Screenshots show the original workspace language. Captions describe the equivalent English controls; menu labels depend on your Databricks language settings.

Before you begin
  • Access to your Databricks workspace and Jira.
  • Permission to create a Git folder and a Databricks App.
  • Access to the Azure OpenAI secret, SQL warehouse and an MLflow experiment. Ask your workspace administrator to grant access if needed.

Your workspace names and IDs are configured in databricks.yml → variables. These are separate from your Jira credentials.

After a restart or deployment

Select Remember for my account when connecting to keep an encrypted copy in your personal workspace folder. After signing in again, the app can restore it for up to 30 days and checks it against Jira. This option requires one-time administrator setup. Without it, enter the token again after a restart or session expiry. Create a new token in Jira if it has expired or been revoked. Use Disconnect and forget saved token to delete the saved copy.

Without administrator setup: after you click Connect, your browser (Edge/Chrome) offers to save the token in its password manager. Accept, and the next time it fills in the token field for you. The app itself stores nothing in the browser.

Update the app and share access

Open the Git folder → Branch → Pull. Deploy the app again and reload with Ctrl+Shift+R. Use Share / Permissions to choose who can use the app. This does not automatically grant Jira or table permissions.

UNDERSTAND

What are skills?

A skill is a saved set of instructions for a recurring task. Invoke it in chat with /name.

Example: weekly report

Instead of writing the same instructions every week, send /weekly-report last week. The agent receives the saved workflow and your additional request.

TermExampleWhat happens?
ToolSearch Jira issuesPython code calls Jira.
SkillWeekly reportInstructions define which issues to find and how to summarize them.
RuleRespond in EnglishA general preference from Settings applies to the conversation.

A skill does not add technical capabilities or access rights. Jira changes still require approval with yes CODE.

Use an existing skill

  1. Type / in chat, at the start of a message or anywhere inside it, for example Please run /triage on ABC-123.
  2. Select a skill, such as /triage, /weekly-report or /issue-summary.
  3. Add an issue key or time period if needed and send.

Inside a message only skills that exist are recognized, so file paths like /tmp/log.txt or web addresses are left alone. You can name up to three skills in one message.

Create a personal skill

Open Settings → Skills → + New skill. Enter a name, short description and instructions. Example:

Name: issue-check
Description: Checks whether an issue is clearly described

1. Read the specified issue.
2. Check for the problem, expected behavior and reproduction steps.
3. List missing information. Do not change the issue.

Save the skill and use /issue-check ABC-123. Personal skills are for you only and are stored in your workspace user folder using your Databricks permissions.

Share a skill with your team

  1. Choose Publish to catalog on a personal skill (visible when the administrator has enabled the shared skill catalog; see docs/REGISTRY.md).
  2. Your colleagues then see it in Settings → Skills with a purple Catalog vN · your name badge and can use it with /name. Changes become a new version via Publish new version.

Published versions cannot be edited. As the owner you can take a skill out of the catalog again with Remove from catalog; it disappears for everyone and you can publish it again later. Delete removes only your personal copy.

Developers can also add a skill to the repository so that it ships with the app as a team skill: copy it from the skill list (View) into the AI chat for your project copy and send:

Read AGENTS.md and .claude/skills/team-skill/SKILL.md. Add the skill below to skills/, validate its format and run the tests. Show me the change before deployment.

After review and deployment, users of this app see the team skill in the / list. Team skills take precedence over personal and catalog skills with the same name.

Skill file format for developers
---
name: issue-check
description: Checks an issue for missing information
---
1. Read the specified issue.
2. List missing information without changing the issue.

App skills in skills/ guide the Jira agent. Development instructions in .claude/skills/ guide the AI assistant editing the code.

Enable “Remember for my account”

A disabled checkbox means that a prerequisite is missing. Updating the code alone does not create the encryption secret.

  1. App administrator: create the separate Fernet encryption secret in a restricted secret scope. The configured names are variables.token_encryption_secret_scope and variables.token_encryption_secret_key in databricks.yml.
  2. Add the app secret resource jira-token-key with READ access. Bind JIRA_TOKEN_ENCRYPTION_KEY to that resource. For bundle deployments, activate both prepared optional blocks in databricks.yml so the next deployment keeps the binding.
  3. Deploy/restart the app and reopen it. You should now be able to select Remember. If the message asks you to sign in again, check User Authorization, the workspace.workspace scope and user-token forwarding, then sign in again.
  4. If the encryption secret is reported as misconfigured, ask the administrator to validate the existing Fernet key. Do not overwrite a working key: saved tokens depend on it.

Full administrator setup instructions. Keep secret values out of chat and source code.

Until setup is complete, Connect still works for the current session. Remember stays disabled rather than storing the token without encryption.

User scopes: allowed APIs

The app requests these API scopes during user authorization. They do not extend your own permissions.

ScopeUse
sqlRun SQL with your permissions: read-only chat queries, and publishing skills to the shared catalog.
catalog.catalogs:readList catalogs.
catalog.schemas:readList schemas.
catalog.tables:readShow tables and metadata.
workspace.workspaceSave personal settings and skills in your workspace user folder.

Three requirements for a table query

  1. The app has the appropriate user scopes.
  2. You have access to the warehouse, catalog, schema and table.
  3. You selected and saved the table under Settings → Data sources.

Selecting a table does not grant permissions. SQL queries use your forwarded user token.

What is stored where?

Plaintext session keys, temporary files and approval codes are kept in memory. Run exactly one worker. An optional remembered Jira token is stored encrypted in your personal workspace folder, bound to your account, app and Jira instance. The separate encryption key comes from an app secret; no token is stored in browser storage. Settings and personal skills are stored in the workspace user folder. Team skills are in the repository. Chat history is separate: without the optional database, the chat frontend does not store a persistent history.

EVERYDAY USE

Using the agent

Jira not connected yet?

Create and enter your token.

What can I ask?

The agent can create and edit issues, change status and priority, link issues and log work. For example: “Create a test issue in project ABC and assign it to me.” It asks for required fields and requests approval before every change. Use /issue-draft for a reusable creation workflow.

Built-in ticket workflows: /show-ticket ABC-123 shows a ticket and its Jira link; /search-tickets my open tickets in ABC uses structured search filters; /edit-ticket ABC-123 change the summary to … prepares a before/after preview and asks for approval. You can also describe these tasks in normal language.

Tool calls start collapsed. Click the row to inspect parameters and results. Status remains visible; errors and approval requests are also explained in the agent's answer.

Attach files

Use /file-analysis to analyze documents and tables step by step. Examples: “Summarize the first three pages of this scanned PDF.” · “Sum the amount by status and make a bar chart.” · “Export only the open entries to Excel.”

PDF text is read page by page; scans and layout are rendered and provided to the image model. Up to 6 visual PDF pages per request are supported. Continue long documents in another message. Small or blurred text may remain unreadable.

Table calculations use all loaded rows, not just the preview. Specify the worksheet for Excel files with multiple sheets. The agent asks about ambiguous number formats. Recalculate Excel formulas in Excel first if cached results are missing. Limits: 100,000 rows, 200 columns and 2 million cells; larger files are explicitly rejected.

Attach screenshots and photos as PNG, JPEG or WebP and ask “What do you see here?” or “What error does this screenshot show?” The app sends image input to the configured image-capable model. Attachments belong to their chat; unique references distinguish files with the same name. Reattach unreadable images or expired files.

Use the paperclip next to Send, paste with Ctrl+V or drag and drop onto the input field. The file appears as a small preview above the input (click × to remove it); add what you want the agent to do and send.

Supported: PNG/JPEG/WebP, CSV, Excel (XLSX/XLSM), PDF (text and visually read scans), TXT/MD/JSON. Images: max. 5 MB each, at most 4 images and 10 MB of image data per request; other files: max. 20 MB. Files are held only in memory and expire after 60 minutes.

Skills: saved workflows with /

Type /, choose a skill, and add details if needed, for example /weekly-report last week. You can also write the skill inside a sentence, for example Please do /triage for ABC-123. Team skills include /triage, /weekly-report and /issue-summary.

Create personal skills under Settings → Skills → + New skill. Enter a name, short description and step-by-step instructions as you would explain them to a colleague. They are visible only to you and are saved in your workspace user folder. To share one, choose Publish to catalog and follow Share a skill with your team.

Approve changes

Before changing anything in Jira, the agent shows exactly what will happen and an approval code. Click Approve action (yes CODE) below the answer, or reply yes CODE, to execute it. Decline cancels the proposal. Otherwise no change is made. Codes are valid for 10 minutes and can be used only once. Repeated approvals show the saved result. After a connection error, first check Jira to see whether the change was already applied. Legacy ja CODE replies are still supported.

Auto-approve (optional): the button Auto-approve: off in the header turns on automatic approval for the next 5 proposed actions in this browser tab. It is off by default, turns itself off after 5 actions, and resets when you close the tab. The app still requires the normal yes CODE message, which your browser then sends for you. Use it only for trusted work: text in Jira tickets or files could trick the agent into proposing unwanted changes, and with auto-approve they run without your check.
