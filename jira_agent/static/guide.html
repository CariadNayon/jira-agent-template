1. Jira verbinden (einmal pro Sitzung)

  1. In Jira oben rechts auf Ihr Profilbild → Profil klicken.
  2. Links Personal Access Tokens → Token erstellen. Namen vergeben (z. B. „Jira Agent“), Ablaufdatum wählen, erstellen.
  3. Token kopieren und im Chat oben in das gelbe Feld „Jira verbinden“ einfügen → Verbinden.

Der Token liegt nur im Arbeitsspeicher der App und gilt nur für Sie. Nach einem Neustart der App, nach dem Abmelden oder spätestens nach 8 Stunden fragt der Agent erneut danach.

3. Dateien anhängen

Über die Büroklammer neben dem Senden-Knopf, per Strg+V (z. B. aus dem Explorer kopiert) oder per Ziehen auf das Eingabefeld. Im Text erscheint [Datei: name] – dann einfach dazuschreiben, was der Agent damit tun soll.

Lesbar: CSV, Excel, PDF (Text), TXT/MD/JSON. Max. 20 MB. Dateien liegen nur im Speicher und verschwinden nach 60 Minuten.

4. Skills – gespeicherte Abläufe mit /

  • Aufrufen: im Chat / tippen → Liste erscheint → auswählen, ggf. etwas dazuschreiben, z. B. /wochenreport letzte Woche.
  • Team-Skills (für alle): z. B. /triage, /wochenreport, /ticket-zusammenfassung.
  • Eigene Skills: Zahnrad → Skills → + Neuer Skill. Name, Kurzbeschreibung und die Anleitung in Schritten – so, als würden Sie es einer Kollegin erklären. Nur für Sie sichtbar, bleibt dauerhaft gespeichert.
  • Fürs Team freigeben: beim Skill „Für Team vorschlagen“ → Datei wird heruntergeladen → siehe B · Skill fürs Team.

5. Änderungen bestätigen

Bevor der Agent etwas in Jira ändert, zeigt er genau, was passieren soll, und einen Code. Erst mit „Aktion bestätigen (ja CODE)“ bzw. der Antwort ja CODE wird es ausgeführt – sonst passiert nichts.

3. Tool von Hand bauen (für Interessierte)

Neue Datei in jira_agent/tools/ – wird automatisch geladen. Vorlage: example_custom_tool.py.

from jira_agent.tools import ToolContext, tool


@tool(write=True, needs=["jira"])          # ändert etwas → Bestätigung nötig; nur mit Jira-Token
def jira_set_status(ctx: ToolContext, issue_key: str, status: str) -> dict:
    """Ändert den Status eines Tickets, z. B. 'In Arbeit' oder 'Erledigt'.

    issue_key: Ticket-Key, z. B. ABC-123
    status: Name des Statuswechsels oder Zielstatus
    """
    ctx.jira.transition(issue_key, status)
    return {"status": "OK"}
  • Docstring = Beschreibung für das Modell; Zeilen name: Text beschreiben die Parameter.
  • ctx.jira hat fertige Helfer: search, issue, create_issue, transition, assign, comment, set_priority, add_label, link, add_worklog … Außerdem ctx.sql (lesendes SQL), ctx.files (Downloads), ctx.uploads (hochgeladene Dateien).
  • write=True für alles, was etwas ändert – die Bestätigung ist dann erzwungen.
  • Testen ohne echtes Jira: Vorlage tests/test_example_custom_tool.py, dann uv run pytest tests -q.

5. Sicherheitsregeln

  • Keine Keys oder Tokens in Code, Logs oder Tool-Ergebnissen.
  • Alles, was etwas ändert: write=True.
  • SQL nur über ctx.sql + check_readonly_sql (nur SELECT, nur freigegebene Tabellen, nur eingebaute Funktionen).
  • Eingaben prüfen, z. B. JiraClient.check_key().

So bekommen Sie eine eigene Kopie der App – ganz ohne Kommandozeile, direkt im Databricks-Workspace.

Teil 1: Code in den Workspace holen

  1. Links auf Workspace klicken.
  2. Workspace → Users → Ihren Ordner (Ihre E-Mail) aufklappen.
  3. Beim eigenen Ordner auf die drei Punkte ⋮ (Alle Aktionen) klicken.
  4. Erstellen → Git-Ordner wählen.
  5. Repository-URL eintragen und Git-Ordner erstellen: 
    https://github.com/CariadNayon/jira-agent-template.git

Teil 2: App anlegen

  1. Oben rechts über das App-Menü Databricks-Apps öffnen.
  2. App erstellen klicken.
  3. Benutzerdefinierte App erstellen wählen.
  4. Namen vergeben (Kleinbuchstaben und Bindestriche, z. B. agent-jira-team-x) und App erstellen.

Teil 3: Zugriffe einrichten (einmalig)

In der App die Ressourcen mit genau diesen Namen hinzufügen:

NameArtBerechtigung
secretSecret: Scope defmgtai-eu-we-dev-adb-local-secret-scope, Key gpt-4-api-keyLesen
sql-warehouseSQL WarehouseKann verwenden
experimentMLflow-Experiment (für Protokolle)Kann bearbeiten

Unter Autorisierung → Benutzerautorisierung diese Bereiche (Scopes) hinzufügen: sql:restricted-query, catalog.catalogs:read, catalog.schemas:read, catalog.tables:read, workspace.workspace.

Damit liest der Agent Tabellen und speichert Einstellungen mit Ihren Rechten – nie mit denen der App.

Teil 4: Bereitstellen

  1. In der App-Übersicht oben rechts Anwenden bzw. Bereitstellen klicken.
  2. Beim Quellcode-Pfad auf das Ordner-Symbol klicken.
  3. Den Git-Ordner jira-agent-template wählen → Auswählen → Anwenden. Nach 1–2 Minuten ist die App unter ihrer URL erreichbar.

Aktualisieren und Freigeben

  • Neue Version: Git-Ordner im Workspace öffnen → oben auf den Branch (main) → Pull. Danach in der App erneut Bereitstellen. Seite mit Strg+Shift+R neu laden.
  • Wer darf die App nutzen? In der App → Teilen bzw. Berechtigungen.
  • Logs bei Problemen: In der App links Logs.
Alternative für Entwickler: uv run deploy (bzw. der KI sagen „Deploye die App.“) legt App, Ressourcen und Scopes automatisch an – Werte stehen in databricks.yml unter variables.

Die App läuft mit einer Instanz: Keys liegen nur im Arbeitsspeicher und gehen bei Neustart oder Deploy verloren. MLflow-Protokolle enthalten Chat-Inhalte (keine Keys) – Zugriff auf das Experiment daher restriktiv vergeben.
